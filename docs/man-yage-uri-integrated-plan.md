# 만약에 우리 — 통합 기획서

> **이별의 한 장면을 영화 같은 AI 선택형 스토리로 완성하는 유료 웹 콘텐츠 서비스**
> **작성일**: 2026-05-29

---

## 1. 서비스 개요

### 1.1 한 줄 정의

> 사용자가 이별의 순간과 “그때 다르게 하고 싶었던 말”을 입력하면, AI가 개인화된 1화 무료 미리보기와 선택지 기반 5화 완결 스토리를 생성해주는 감정 몰입형 웹소설 서비스.

### 1.2 해결하려는 문제

이별 후회가 남은 사용자는 조언보다 “내 상황과 닮은 이야기 안에서 다른 선택을 해보는 경험”을 원한다.

- 일반 연애 콘텐츠는 내 장면, 내 말투, 내 후회를 반영하지 못함
- AI 챗봇 답변은 작품성이 낮고 저장/공유 가치가 약함
- 상담 서비스는 진입 장벽이 높고 결제 전환까지 심리적 부담이 큼
- 사용자는 “그때 내가 다르게 말했다면?”이라는 감정을 안전한 픽션으로 체험하고 싶어 함
- 유료 결제 후에는 단순히 긴 글보다 “돈이 아깝지 않은 장면, 문장, 결말”이 필요함

### 1.3 핵심 가치 사슬

| ① 입력 | ② 무료 생성 | ③ 선택/분기 | ④ 결제 | ⑤ 유료 완결 |
|--------|-------------|-------------|--------|-------------|
| 이별 순간, 이유, 후회한 말, 기억 디테일 입력 | 1화 미리보기 + 장면 카드 생성 | A/B/C 선택 또는 직접 입력 결말 | PayPal 해외 결제, Toss 국내 결제 예정 | 2~5화 약 50페이지 완결 생성 |

### 1.4 타겟 페르소나

#### 1차 타겟

**페르소나 A: "후회가 남은 20대 여성"**

| 항목 | 내용 |
|------|------|
| 연령 / 성별 | 24~32세 여성 |
| 상황 | 이별 후 마지막 문자나 대화가 계속 떠오름 |
| 핵심 페인 | “그때 화내지 않고 미안하다고 먼저 말했으면 달랐을까?” |
| 사용 시점 | 밤, 퇴근 후, 감정 콘텐츠 소비 중 |
| 본 서비스 가치 | 내 상황과 닮은 1화를 읽고 다른 결말을 선택해볼 수 있음 |

**페르소나 B: "담담한 성장 결말을 원하는 사용자"**

| 항목 | 내용 |
|------|------|
| 연령 / 성별 | 28~40세 남녀 |
| 상황 | 재회보다 감정 정리와 자기 성장에 관심 |
| 핵심 페인 | 흔한 위로 문구는 싫고, 내 감정이 정리되는 작품을 원함 |
| 사용 시점 | 주말, 혼자 있는 시간, 긴 글을 읽을 여유가 있을 때 |
| 본 서비스 가치 | 영화 같은 장면과 마지막 이미지로 감정적 완결감을 얻음 |

**페르소나 C: "SNS 공유형 감정 콘텐츠 소비자"**

| 항목 | 내용 |
|------|------|
| 연령 / 성별 | 18~30세 남녀 |

| 핵심 페인 | “내 얘기 같은 문장”을 캡처하고 공유하고 싶음 |
| 사용 시점 | SNS 체류 중, 친구와 대화 중 |
| 본 서비스 가치 | 캡처하고 싶은 문장과 직접 입력 결말로 공유 욕구 발생 |

**페르소나 D: "이별 콘텐츠 바이럴 허브"**

| 항목 | 내용 |
|------|------|
| 역할 | 연애/이별 콘텐츠 계정 운영자, 커뮤니티 활동자 |
| 특징 | 감정 문장과 선택지형 콘텐츠를 주변에 공유 |

| 본 서비스 가치 | 개인화된 이야기와 문장 캡처로 자연 바이럴 유도 |

### 1.5 시장 크기

#### 전체 시장 규모

| 지표 | 추정 | 근거 |
|------|------|------|
| 국내 웹소설/웹콘텐츠 소비자 | 수백만 명 이상 | 웹툰·웹소설 플랫폼 이용자 기반 |
| 연애/이별 감정 콘텐츠 소비층 | 10~30대 중심 대규모 | SNS, 커뮤니티, 숏폼 소비 패턴 |
| 생성형 AI 개인화 콘텐츠 수요 | 성장 중 | ChatGPT, AI 이미지/글쓰기 서비스 확산 |

#### 도달 가능 시장 (TAM/SAM/SOM)

| 구분 | 정의 | 추정 규모 | 산정 근거 |
|------|------|-----------|-----------|
| TAM | 연애·이별·감정 콘텐츠를 소비하는 전체 사용자 | 수백만~천만 명 | SNS/웹콘텐츠 소비층 |
| SAM | 개인화 AI 스토리 생성에 관심 있는 사용자 | 수십만~수백만 명 | AI 콘텐츠 이용 경험자 |
| SOM | 초기 유료 전환 가능 핵심층 | 1만~5만 명 | 이별 후회, 감정 콘텐츠, 결제 가능층 |

> **주의**: 본 시장 규모는 초기 기획 추정이며, 실제 도달 사용자는 콘텐츠 품질, 결제 UX, SNS 확산성에 따라 달라질 수 있다.

## 2. 핵심 가치 제안

### 2.1 차별화 포인트 4가지

1. **내 장면 기반 개인화**: 장소, 기억나는 디테일, 상대의 말투나 행동을 장면 속 감각적 앵커로 사용
2. **무료 1화로 품질 확인**: 결제 전 작품성, 몰입도, 문체를 확인할 수 있음
3. **선택지 + 직접 입력 결말**: A/B/C 분기뿐 아니라 사용자가 원하는 결말 방향을 직접 입력 가능
4. **유료 완결 보상감**: 2화 초반부터 결제 보상감이 느껴지는 새 장면, 놓친 신호, 기억나는 문장 제공

### 2.2 기존 서비스와의 차이

#### (1) 일반 연애 콘텐츠

| 항목 | 일반 연애 콘텐츠 | 본 서비스 |
|------|------------------|-----------|
| 개인화 | 낮음 | 높음 |
| 입력 반영 | 없음 | 이별 순간, 이유, 말, 장소, 행동 반영 |
| 결말 선택 | 없음 | 선택지/직접 입력 가능 |
| 결제 전 확인 | 제한적 | 무료 1화 제공 |

#### (2) AI 챗봇

| 항목 | AI 챗봇 | 본 서비스 |
|------|--------|-----------|
| 형식 | 대화형 답변 | 작품형 스토리 |
| 저장성 | 낮음 | 스토리 페이지 저장 |
| 장면감 | 불안정 | 프롬프트와 스키마로 장면형 구성 |
| 결제 UX | 일반 구독 | 단건 완결 결제 |

#### (3) 웹소설 플랫폼

| 항목 | 웹소설 플랫폼 | 본 서비스 |
|------|---------------|-----------|
| 콘텐츠 | 작가가 만든 고정 작품 | 사용자별 개인화 작품 |
| 분기 | 제한적 | 선택지 및 직접 입력 |
| 감정 반영 | 독자가 해석 | 입력 단계부터 반영 |
| 바이럴 요소 | 작품 단위 | 내 이야기 같은 문장/장면 |

#### (4) 경쟁사 비교 요약

| 비교 항목 | 일반 AI 글쓰기 | 연애 상담 앱 | 본 서비스 |
|-----------|----------------|--------------|-----------|
| 픽션 고지 | 약함 | 상담 중심 | 명확 |
| 개인화 스토리 | 가능하나 산만 | 약함 | 핵심 기능 |
| 안전 필터 | 서비스별 상이 | 있음 | 개인정보/연락/스토킹 표현 차단 |
| 유료 전환 구조 | 구독형 | 상담 과금 | 무료 1화 → 완결 단건 결제 |

### 2.3 글로벌 벤치마킹

#### Episode / Choices (인터랙티브 스토리)

- 사용자가 선택지를 통해 감정적 몰입을 유지
- 회차 단위 결제 및 스토리 잠금 구조가 검증됨
- **본 서비스 적용**: 무료 1화 후 선택지 기반 유료 완결

#### Character.AI / AI Companion 서비스

- 사용자는 개인화된 감정 반응에 강하게 몰입
- 하지만 실제 인물 예측이나 감정 의존 리스크 존재
- **본 서비스 적용**: 실제 상대의 마음을 예측하지 않는 픽션 고지와 안전한 서사화

#### Wattpad / Webtoon 공유 문화

- 기억나는 문장, 장면, 댓글 기반 확산
- 작품 일부 캡처와 추천이 유입을 만듦
- **본 서비스 적용**: 캡처하고 싶은 문장과 마지막 이미지 설계

## 3. 서비스 범위

### 3.1 콘텐츠 커버리지

| 범위 | 정책 |
|------|------|
| 이별 후회 | MVP 핵심 |
| 재회 상상 | 안전한 픽션으로 제한 |
| 성장/정리 결말 | 핵심 지원 |
| 분노/상처 감정 | 폭력/협박 없이 정서적 해소 중심 |
| 실제 연락 유도 | 금지 |

### 3.2 입력 유형 커버리지

| 입력 항목 | 설명 |
|-----------|------|
| 이별 순간 | 문자로 끝난 밤, 마지막 통화, 카페에서 헤어진 날 등 |
| 이별 이유 | 권태기, 오해, 말실수, 현실 문제 등 |
| 다르게 하고 싶었던 말 | 후회한 말 또는 행동 |
| 장소 | 마지막 장면의 공간 |
| 기억 디테일 | 물건, 날씨, 표정, 소리 |
| 상대 행동 | 말투, 침묵, 자주 보이던 행동 |
| 감정 | 후회, 그리움, 분노, 담담함, 고마움 |
| 결말 방향 | 재회, 성장, 이별, 평행세계 |

### 3.3 생성 깊이 단계

```text
[Stage 1: 입력 검증/안전 필터]        ← Free
        ↓
[Stage 2: 1화 미리보기 생성]          ← Free
        ↓
[Stage 3: 장면 카드 생성]             ← Free
        ↓
[Stage 4: 선택지/직접 입력 저장]      ← Free
        ↓
[Stage 5: 2~5화 유료 완결 생성]       ← Paid
```

## 4. 서비스 흐름

> **변동 가능성 안내**: 본 섹션의 흐름은 초기 설계안이며, 사용자 테스트, 결제 정책, 생성 품질 개선에 따라 조정될 수 있다.

### 4.1 스토리 생성 흐름

```text
[1] /create 진입
       ↓
[2] 이별 순간/이유 선택
       ↓
[3] 다르게 하고 싶었던 말 입력
       ↓
[4] 장소, 기억 디테일, 상대 행동 입력
       ↓
[5] 감정/원하는 결말/별명 입력
       ↓
[6] 픽션 고지 및 개인정보 미입력 동의
       ↓
[7] 1화 무료 생성
       ↓
[8] /stories/{id}/preview 이동
```

### 4.2 미리보기 및 선택 흐름

```text
[1] 1화 미리보기 읽기
       ↓
[2] 장면 카드 확인
       ↓
[3] 선택 방식 결정
    - A/B/C 기본 선택지
    - 기타: 직접 입력 결말
       ↓
[4] 선택지 저장
       ↓
[5] /checkout/{storyId} 이동
```

### 4.3 결제 흐름

```text
[1] 체크아웃 진입
       ↓
[2] 상품/선택 방향 확인
       ↓
[3] PayPal 또는 Toss 결제 선택
       ↓
[4] 서버 결제 검증
       ↓
[5] 결제 완료 시 유료 회차 생성
       ↓
[6] /stories/{storyId} 리더 이동
```

### 4.4 유료 완결 생성 흐름

```text
[1] 결제 완료 확인
       ↓
[2] 선택지 또는 직접 입력 결말 조회
       ↓
[3] OpenAI에 2~5화 생성 요청
       ↓
[4] 약 45~55페이지 분량 검증
       ↓
[5] Supabase story_chapters 저장
       ↓
[6] payment.status=paid, story.status=completed
```

### 4.5 독자 리더 흐름

```text
[1] 완결 페이지 진입
       ↓
[2] 1화부터 순차 읽기
       ↓
[3] 회차별 선택지 확인
       ↓
[4] 다음 회차 열람
       ↓
[5] 마지막 장면에서 완결감 제공
```

### 4.6 사용자 피드백 흐름

```text
[1] 완결 읽기 후 만족도 질문
       ↓
[2] "돈이 아깝지 않았나요?" 평가
       ↓
[3] 캡처하고 싶은 문장 선택
       ↓
[4] 공유 카드 생성 또는 피드백 저장
```

│  └────────────────────────────┬─────────────────────────────────┘    │
│                               ↓                                      │

## 6. AI 생성 엔진 상세 구현

> **변동 가능성 안내**: 본 섹션의 프롬프트 구조와 분량 기준은 MVP 검증 결과에 따라 계속 조정될 수 있다.

### 6.1 단계별 처리 흐름

#### Stage 1: 입력 검증

```text
[입력] 사용자가 작성한 이별 정보
[처리]
1. 필수 필드 검증
2. 길이 검증
3. 개인정보/위험 표현 1차 필터
[출력] 안전한 StoryInput
```

#### Stage 2: 무료 1화 생성

```text
[입력] StoryInput
[처리]
1. previewPrompt 구성
2. OpenAI Responses API 호출
3. zodTextFormat으로 JSON 구조 강제
4. body_paragraphs를 body로 병합
[출력] PreviewStory
```

#### Stage 3: 장면 카드 생성

```text
[입력] StoryInput + PreviewStory
[처리]
1. scene_no, scene_title, setting, body, dialogue 생성
2. visual_prompt 생성
3. story_scenes 저장
[출력] 3~5개 장면 카드
```

#### Stage 4: 선택지/직접 입력 저장

```text
[입력] choiceId 또는 customChoiceText
[처리]
1. A/B/C 선택 검증
2. 직접 입력은 5~160자 제한
3. 연락/찾아가기/개인정보/협박/자해 표현 차단
4. 직접 입력은 C 슬롯 label로 저장
[출력] choice_selected 상태
```

#### Stage 5: 유료 완결 생성

```text
[입력] StoryInput + selectedChoice
[처리]
1. paidPrompt 구성
2. 2~5화 생성
3. 회차당 5,000~6,500자 검증
4. 전체 45~55페이지 목표
[출력] paid chapters
```

### 6.2 생성 비용 분석

| 단계 | 호출 | 비용 특성 |
|------|------|-----------|
| 무료 1화 | OpenAI 1회 | 약 20원 내외 추정 |
| 유료 완결 | OpenAI 1회 | 약 100~200원 내외 추정 |
| 결제 검증 | PayPal API | 결제 수수료 외 호출 비용 없음 |
| 저장 | Supabase | 무료 플랜 내 가능 |

- 무료 1화 → 유료 완결의 명확한 전환 구조
- PayPal 해외 결제와 Toss 국내 결제 확장 가능
- 감정 콘텐츠와 웹소설 사이의 새로운 포지션

### 13.2 약점

- AI 생성 품질이 모델 응답에 의존
- 민감한 감정 주제를 다루므로 안전 설계 필요
- 결제 후 만족도 기준이 높음
- 단건 결제 모델의 반복 구매 구조 검증 필요

### 13.3 지속 가능한 경쟁 해자

| 해자 | 설명 |
|------|------|
| 사용자 입력-결말 데이터 | 어떤 입력이 결제로 이어지는지 축적 |
| 프롬프트 품질 | 돈이 아깝지 않은 유료 완결 구조 |
| 바이럴 문장 데이터 | 공유되는 문장 패턴 학습 |
| 결제 전환 UX | 무료 1화와 선택지 기반 체크아웃 최적화 |

### 13.4 검증 가능성

- 지인/베타 사용자 5~30건 생성으로 즉시 품질 검증 가능
- PayPal Sandbox로 결제 흐름 검증 가능
- Toss 심사 후 국내 결제 전환율 측정 가능
